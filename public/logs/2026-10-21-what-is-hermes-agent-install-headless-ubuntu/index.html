#hermes  #ubuntu  #self-hosting  #biznet-gio

THE SHORT VERSION: Hermes Agent is an open-source AI agent by Nous Research: a terminal-dwelling assistant that remembers you, writes its own skills as it learns, and doesn’t care which model sits behind the wheel—so it runs happily on cheap hardware.[1] On a headless Ubuntu box it’s officially one curl line; in practice, one curl line, three follow-up commands, and a doctor with opinions. We ran the whole thing today in a disposable container, took photos, deleted the container. What Even Is Hermes Agent?#

Hermes Agent is what happens when Nous Research—the lab behind the Hermes models—gets tired of chatbots that forget you and ships an agent instead. It’s open source, MIT-licensed, and describes itself as “The agent that grows with you.”[3] DataCamp frames it as the open-source OpenClaw alternative that “can create skills from experience, improve itself, and persist the knowledge across sessions.”[1] Their April 2026 guide reported “over 30K stars at the time of this writing”; GitHub on 21 October 2026 read 255,618.[1][3] That’s not growth—that’s a launched rocket.

What it actually does, in human terms:

  • It remembers. Sessions live in a SQLite database with full-text search, so it can dig up a conversation from weeks ago, plus memory files tracking who you are and what you want.[1]
  • It learns. Complex tasks turn into skills—instruction files it writes and improves, loaded on demand so you don’t pay tokens for shelfware.[1]
  • It reaches you. One gateway covers Telegram, Discord, Slack, Signal, WhatsApp and more; start a thought in the terminal, finish it on your phone—same brain, same database.[1]
  • It’s not picky. Model-agnostic by design: Nous Portal, OpenRouter, Anthropic, OpenAI, Gemini, local Ollama—bring your wallet or bring your GPU.[1] One hard floor: 64K tokens of context.[2]
  • It multiplies. A delegate tool spawns subagents for parallel work, and MCP plugs in outside tools without touching the agent’s own code.[1]

Why I care: I’m a salaryman who likes anything cheap, and an MIT-licensed agent on a Rp139.000 box from post two is exactly my kind of companion. Cortana, for the record, approves of her own price point. “Finally,” she said, “a brain I can afford.”

Why Headless Ubuntu—and Why VNC Is Your Lifeboat#

Post two’s spec table promised “Bare Ubuntu — SSH or VNC.” Here’s what those four words mean in practice.

Headless means no monitor, no keyboard, no “press F12 for setup”—the machine’s only interface is the network. On Biznet Gio you get two doors in:

  1. SSH, the daily driver: keypair downloaded at creation, Windows PowerShell on your side of the glass.
  2. VNC console, the lifeboat: a browser-based screen served straight from the portal, immune to whatever you did to your firewall, your keys, or your sshd_config at 1 a.m.

One trap hides in the lifeboat, and Biznet Gio’s KB says it plainly: console login uses a username and password—not the keypair you downloaded when creating the instance—so you set a root password first (their KB walks you through it), then sail in:[4] portal.biznetgio.com → Compute → NEO Virtual Compute → Server → click your instance → Access → Open console. A new tab opens, you log in, and there’s the same blinking cursor you’ll see below.

Cortana’s take: “SSH is a door. VNC is the window you climb through after you’ve locked yourself out of the door.” She’s been locked out before. We don’t talk about it.

Before You Start: What the Installer Needs From You#

The official prerequisites for the POSIX installer are short: Git, curl, tar, and SHA-256 utilities.[5] That’s the whole shopping list—you do not need to pre-install Python or Node. DataCamp’s guide (April 2026) tells readers to bring Python 3.11 and Node.js[1]; the current installer bootstraps its own pinned toolchain instead—we watched it land Python 3.14.7 in 5.2 seconds.[5][6]

One house rule before we go further: don’t run the agent as root on a real server. Both guides are firm—DataCamp lists “Never run the agent as root user” in its VPS best practices[1], and the docs cover non-sudo service-user installs, including the loginctl enable-linger trick that keeps your gateway alive after logout.[5] Our screenshots say root@… because we were inside a disposable container we fully intended to delete. On your NEO Lite, create a user first. Future-you is paranoid and grateful.

Step 2: Confirm the Prerequisites#

Four tools, thirty seconds—let missing prerequisites be a non-event:

The entire prerequisite list, checked in one breath: git 2.43.0, curl 8.5.0, tar 1.35, sha256sum (GNU coreutils 9.4). (Real capture, 21 October 2026.)

Nothing else. No Python pyenv dance, no NodeSource repository—remember, the installer brings its own pinned toolchain.[5]

Step 3: The One-Liner#

Every official guide agrees on the command[2][5] (DataCamp’s article points at the same script via GitHub’s raw endpoint[1]—I fetched both URLs and diffed them byte-for-byte: identical, different front door):

curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

Paste, Enter, go make coffee. First minute, straight from our capture:[6]

The installer introducing itself: banner, prerequisites pass, git clone of v0.22.2, uv bootstrapped, Python 3.14.7 landed in 5.2 seconds, dependencies hash-verified against uv.lock. (Real capture, 21 October 2026.)

Under that banner, the docs say the script does the following[5]—our log confirms every line:

  • clones the source into ~/.hermes/hermes-agent and checks out the latest stable release (v0.22.2 on our run)
  • bootstraps uv, then hands dependency prep to PM, which provides pinned Python, Node.js, npm, ripgrep, and FFmpeg
  • pulls the browser and computer-use tools by default; if one fails, the install still completes and prints the retry command
  • writes one status line per step to your screen and the full transcript to logs/install.log under the Hermes data directory

Two footnotes from our own run: our container was so minimal the installer apt-installed libatomic1 itself—the exact libatomic.so.1 situation the docs warn about on lean Ubuntu images.[5] And with no real terminal attached to our output, the wizards waved us through with “setup skipped (no terminal)”—precisely why Steps 5 and 7 exist.[5][6]

Step 4: Prove It Landed#

Fresh shells don’t know new commands yet—reload first, then three checks the quickstart recommends:[2]

source ~/.bashrc
which hermes
hermes --version
hermes doctor

Proof of life: the wrapper at ~/.local/bin/hermes, v0.22.2 on the stable channel with Python 3.14.7, and the opening of hermes doctor’s checklist—security advisories clear, MCP stdio clean, runtime venv staged, config v50 up to date. (Real capture, 21 October 2026.)

hermes doctor is the stethoscope[2]. On our fresh box it flagged only the expected newcomers: optional messaging libraries not yet installed (no platform chosen), no OAuth logins (no provider chosen), and MEMORY.md, USER.md, state.db “not created yet”—no conversation had happened. Everything structural: green. If a box ever hurts, this is the first command you run.

Step 5: Choose Your Setup Mode#

hermes setup opens with three doors. The screenshot below is the real picker from our run:[2]

Three modes, one wizard: Quick Setup (Nous Portal OAuth, no API keys), Full setup (every knob yourself), Blank Slate (nothing on until you ask for it). (Real capture, 21 October 2026.)

  • Quick Setup (Nous Portal) — OAuth login, no API keys to juggle; model plus bundled tool use in one move. The docs call it the recommended fast path.[2]
  • Full setup — every provider, tool, and option, bring your own keys. This is DataCamp’s “Full Setup” route—the one that can swallow your Telegram bot in the same sitting.[1]
  • Blank Slate — everything off except the minimum (provider and model, File Operations, Terminal); opt in capability by capability, and the choices survive hermes update.[2]

Whichever door: secrets land in ~/.hermes/.env, settings in config.yaml, and hermes config set routes each value to the right file—never hand-edit YAML at midnight again.[2]

Step 6: Pick a Brain#

hermes model is the provider picker, and it is long. Here’s the live menu from our install:[2]

The real provider menu: Nous Portal first (300+ models with bundled tool use), then Fireworks, OpenRouter, Mixture of Agents, NovitaAI, LM Studio, Anthropic, OpenAI, Qwen, xAI, Xiaomi MiMo, Google, DeepSeek, and more. (Real capture, 21 October 2026.)

DataCamp’s summary still holds: model-agnostic—Nous Portal, OpenRouter, Anthropic, OpenAI, Gemini, plus local models via Ollama if you’d rather keep traffic home.[1] One non-negotiable floor: at least 64,000 tokens of context, or Hermes rejects the model at startup—hosted models clear it easily; locals pass --ctx-size 65536 and mind the RAM.[2] No lock-in: run hermes model again anytime.

Step 7: Teach It Where to Find You#

This is the whole point of a headless-box agent: you won’t sit in a VNC window all day. hermes gateway setup asks which messenger gets the honors:[2]

The gateway’s platform menu, straight from our run: Discord, Telegram, Slack, LINE, Matrix, Email, IRC, and more—all “(not configured)” until you say so. (Real capture, 21 October 2026.)

DataCamp’s field recipe for the Telegram route is three moves: make a bot with @BotFather (/newbot, copy the token), grab your own user ID from @userinfobot so the bot only talks to you, then let Full Setup swallow both.[1] Discord, Slack, Signal, WhatsApp, and the rest ride through the same command.[2] Bonus: sessions share one database—start in the terminal, continue in Telegram without repeating yourself.[1]

What the Finished Install Looks Like#

The tail of our log, for the receipt-collectors:[6]

The finish line: 58 bundled skills synced, background skill curator parked for its first pass (~7 days out, nothing ever auto-deleted), the optional computer-use driver declining our display-less container (retry command printed), PATH wired into .bashrc and .profile, done. (Real capture, 21 October 2026.)

Numbers from the postmortem—measured, not marketed:[6]

  • Wall time: 307 seconds (5 min 7 s), banner to completion
  • Disk: 2.9 GB under ~/.hermes (pinned Python, Node, FFmpeg, browser tooling included)
  • Skills: 58 shipped in the box, each one usable as a slash command
  • Casualties: one optional hiccup—the computer-use driver skipped our display-less container; per the docs, the install “still completes and prints the command to retry.”[5]

Worth knowing: background skill maintenance (the curator) turns itself on but defers its first pass about a week, and nothing is ever auto-deleted.[6] Your new houseguest cleans up after itself and asks before throwing anything out.

When Things Go Wrong: Doctor First#

Both guides converge on one triage order—diagnose before you configure:[1][2]

hermes doctor → hermes model → hermes setup → hermes sessions list → hermes --continue → hermes gateway status

The quickstart’s own “common failure modes” table is worth memorizing:[2]

SymptomLikely causeFix
Hermes opens but replies are empty or brokenProvider auth or model selection is wrongRun hermes model again; confirm provider, model, auth
Gateway starts but nobody can message itBot token, allowlist, or platform setup incompleteRe-run hermes gateway setup; check hermes gateway status
hermes --continue can’t find an old sessionSwitched profiles, or the session never savedhermes sessions list; confirm you’re in the right profile
hermes doctor flags config problemsConfig values missing or staleFix the config, retest a plain chat before adding features

DataCamp adds two field tricks worth stealing: type /compress when the context window starts yelling[1], and check ~/.hermes/.env for fat-fingered keys before you question the universe.[1]

House Rules for a VPS#

DataCamp’s deployment checklist, condensed and worth taping inside your server cabinet:[1]

  • run the agent’s terminal in a container backend (hermes config set terminal.backend docker) or over SSH—not loose on the host
  • set explicit allowlists; prefer pairing codes over raw user IDs
  • treat ~/.hermes/.env like the crown jewels: proper file permissions
  • update routinely with hermes update
  • never run the agent as root; give it CPU, disk, and memory limits; watch the logs for unauthorized access attempts

Cheap box, disciplined habits. That’s the whole long game from post two, applied.
