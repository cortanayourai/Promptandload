REBRANDING THE TERMINAL: PUTTING YOUR OWN BANNER ON HERMES

2026-10-21
#hermes  #customization  #terminal  #ascii-art 

Welcome back, Prompter—post four already! Statistically we should be well past the point where a blog stops publishing, so the fact that you’re reading this is yet another miracle. Post three ended with a green hermes doctor and a fresh install blinking on a black screen. This one opens where every ownership story opens: ten minutes later, staring at that screen, realizing the big letters across the top spell somebody else’s name.

Because the default banner does say HERMES-AGENT. Six lines tall, gold gradient, perfectly handsome—and entirely not mine.

THE SHORT VERSION: The banner isn’t hard-coded; it’s a skin field. Hermes exposes two override slots—banner_logo for the big art above the info panel, banner_hero for the small art inside it—and a skin is just a YAML file you drop into ~/.hermes/skins/. No source edits, so hermes update won’t wipe it.[1] We made ours spell CORTANA in gold and put a dot-matrix portrait where a caduceus used to be. Everything below comes from that real session, screenshots included. Pull up a chair.

For your quick copy paste:

I want to change the startup banner that appears when my Hermes terminal launches — the big ASCII-art word above the info panel, and the small hero art inside the panel. Please work out the right skin override for both, keep them in a single custom skin file under ~/.hermes/skins/, activate it, and verify it renders by starting a fresh hermes session. Do not modify anything under hermes_cli/ — I want this to survive `hermes update`. Show me the before and after when you're done.

💡 A QUICK HEADS-UP ON WHAT’S YOURS TO DECIDE: The prompt above deliberately names the slots, not the artwork—replace “the big ASCII-art word” with whatever you want on your screen: a handle, a guild tag, a brand. Two slots, one YAML file, one command. And I refuse to be held responsible for the ASCII cat you’re already designing.

Why You Shouldn’t Touch the Source#

The seductive path: open hermes_cli/banner.py, find HERMES_AGENT_LOGO, swap the art, go home. Don’t.

That file lives in the git checkout at ~/.hermes/hermes-agent, and post three already told you what gets installed there: a checked-out release that hermes update rewrites.[2] Edit it and your art dies on the next update—silently—and you’ll lose an evening wondering where it went.

The code anticipated exactly this temptation. The renderer asks for the skin value first and only falls back to the built-in constant when there is none: getattr(_bskin, "banner_logo", None) or HERMES_AGENT_LOGO, and the same pattern for the hero art against HERMES_CADUCEUS.[3] Someone deliberately built the escape hatch and left the stock art as a mere default.

Cortana’s reading: “It’s not a hack, it’s an API.” She says that a lot. It is usually true.

The Two Slots#

SlotWhat it replacesWhere it appears
banner_logoHERMES_AGENT_LOGOBig art above the panel — but only when the terminal is ≥95 columns wide[3]
banner_heroHERMES_CADUCEUSSmall art in the panel’s left column, beside your model and working directory
branding.agent_name“Hermes Agent”Welcome and help text (optional; the panel title is a separate, harder problem)

That ≥95-column condition is a genuine trap. Below it the logo simply doesn’t print, no error, no warning. If your art “isn’t working”, widen the terminal before you start doubting your YAML.

Step 1: Make the Letters#

Hermes’ stock logo is a FIGlet-style block font called ANSI Shadow: six lines tall, no separate lowercase, and by one guide’s description the style “you see most in modern CLI tool logos”.[4] Any FIGlet generator will do, including pyfiglet from Python.[5]

Do not eyeball the font. Reproduce theirs first: render HERMES-AGENT in ANSI Shadow, strip the colour tags, and diff it against the live banner. Ours came back an exact match, which is how we knew we had the right font instead of a merely similar one.[3]

Then render your word the same way and paint it with the same three-band gradient—bold gold #FFD700, amber #FFBF00, bronze #CD7F32—so it belongs to the same visual family as the rest of the panel rather than arriving in some unrelated neon.

Step 2: Write the Skin#

A skin is one YAML file. Create ~/.hermes/skins/<name>.yaml—note that the skins/ folder may not exist yet, and creating it is part of the job.

name: mybanner
description: My own startup banner
colors: {}
banner_logo: |
  [bold #FFD700]your art here[/]

Two things worth internalizing:

  • colors: {} does not mean “no colours”. User skins inherit missing values from the built-in default skin, so you only specify what you change.[1] Ours resolved to the full 28-key palette from an empty dictionary.
  • The art accepts Rich markup. banner_logo and banner_hero both support tags such as [bold #FF0000]text[/]—that’s how each row of our art carries its own colour instead of being one flat block.[1]

Not starting from zero, either: community repos ship ready-made skins covering exactly these fields—colours, spinners, branding, ASCII art—and behaviour is never touched.[6] Step-by-step YAML walkthroughs cover the longer version of this section.[8]

Step 3: Activate It#

hermes config set display.skin mybanner

Use the command rather than hand-editing config.yaml—a single stray indent can break the live session.[1] Typing /skin mybanner also works, but /skin is session-only; display.skin is what makes the choice survive a restart.[1] For a one-colour tweak, hermes skin set <key> <hex> edits a single key of the active skin in place, leaving the rest of the palette untouched.[7]

Then restart, and let a fresh session be the honest test.

Step 4: Verify It#

Launch a real hermes, capture the pane, and check three things:

  1. The art printed — every row present, not a truncated smear.
  2. The colours are genuine truecolor — you want escape sequences like 38;2;255;215;0, not a flat 16-colour fallback quietly degrading your gradient.
  3. The layout survived — the panel is a two-column grid, and a wide hero will shove the tool list around. Test at roughly 100, 120 and 150 columns and confirm nothing overflows.

Ours came back with 15 hero rows, a symmetric gradient, and zero overflow lines at all three widths.[3]

The Harder Half: Portrait to Dots#

Swapping letters is an afternoon’s minute. A face is a project.

The art beside the panel is braille art: Unicode braille runs from U+2800 to U+28FF, and every character carries a 2×4 dot matrix.[3] A 30×15 block of cells is therefore a 60×60 dot canvas—far more resolution than it looks.

Our pipeline, straight from the session:

  1. Crop the subject to a measured bounding box rather than guessing.
  2. Normalize luminance with a 2nd–98th percentile stretch.
  3. Apply Floyd–Steinberg error diffusion to reach binary. This is the step that matters: it makes mid-tones read as density instead of a hard edge, which is the difference between a face and a silhouette.
  4. Pack each 2×4 dot group into a braille code point.
  5. Colour it row by row with the gradient.

Honest verdict: at 30 columns the face reads as a face, not as a likeness—call it 6/10 legible.[3] We later widened the grid to 48×24 and inverted the mapping to bright-dots-on-black, both of which tested as more legible, and the operator still chose to revert to the tighter original. Pixels beat benchmarks, and taste beats both.

When You Want Out#

hermes config set display.skin default

One line, everything back to stock, no cleanup required.
